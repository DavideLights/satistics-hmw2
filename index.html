Step 1

Entropy & BIP-39: Mnemonic Phrase & 512-bit Seed

CSPRNG → PBKDF2-HMAC-SHA512

Raw cryptographically secure entropy is sampled from OS randomness. A SHA-256 checksum is appended (4 bits for 128-bit entropy, 8 bits for 256-bit entropy). The concatenated bitstream is partitioned into 11-bit chunks, each indexing a standardized 2,048-word dictionary. Finally, the phrase is stretched into a 512-bit seed via PBKDF2-HMAC-SHA512 (2,048 iterations, salt = "mnemonic" + passphrase).

Step 3

secp256k1: Elliptic-Curve Public-Key Computation

Q = k · G ∈ E(𝔽p)

The private key scalar k ∈ [1, n-1] multiplies the standard base generator point G over the Koblitz curve y² ≡ x³ + 7 &pmod; p. Computing Q = k · G is fast via double-and-add; computing k from Q requires solving the Elliptic Curve Discrete Logarithm Problem (ECDLP), which is computationally infeasible.

Keccak-256: Public Key Compression & Address Truncation

Sponge Construction → Last 20 Bytes

Ethereum drops the leading 0x04 prefix byte, leaving the 64-byte payload Qx ∥ Qy. This byte array is hashed with Keccak-256 (the original sponge function before NIST FIPS 202 padding changes). EIP-55: Mixed-Case Error-Detection Checksum Encoding

Casing ≡ keccak256(ascii_addr) Nibble ≥ 8

To prevent catastrophic typos without altering address length or breaking compatibility, EIP-55 hashes the ASCII string representation of the lowercase address with Keccak-256. For each hex character ai, if it is a letter (a–f) and the i-th nibble of the hash is ≥ 8, it is capitalized; otherwise, it remains lowercase. Digits 0–9 are unchanged.

3. STATISTICAL PROPERTIES & VISUAL VERIFICATION

Empirical Validation of PRF Uniformity & SAC

A. Uniformity & Entropy Preservation Across the Pipeline

True non-deterministic physical entropy is sampled only at the initial CSPRNG step (128 or 256 bits). Every downstream transformation is 100% deterministic. However, because HMAC-SHA512 and Keccak-256 act as cryptographically secure Pseudorandom Functions (PRFs) and randomness extractors, their intermediate outputs are computationally indistinguishable from uniform distributions over their target spaces.

B. Strict Avalanche Criterion (SAC) & Bit-Flip Experiment

The Strict Avalanche Criterion states that flipping any single input bit must cause each output bit to flip with probability p ≈ 0.5. In Keccak-256, changing 1 bit in the private key or entropy flips approximately 128 of the 256 output bits.

C. EIP-55 Typo Detection Probability & Live Tamper Test

Because an Ethereum address contains 40 hex characters and roughly 40 × (6/16) ≈ 15 alphabetic characters (a–f), random casing yields 215 = 32,768 distinct states. A random typing typo or wrong casing has only a 1 in 32,768 chance of accidentally matching the hash nibbles, giving an empirical 99.997% error detection rate.

A. Core Cryptographic Distinctions

A secure blockchain wallet pipeline combines diverse mathematical constructs. Confusing their distinct operational guarantees is a primary source of architectural vulnerabilities:

B. Why Multiple Primitives Instead of One Single Algorithm?

Separation of Concerns & Algebraic Incompatibility

It is mathematically impossible for a single cryptographic primitive to serve all stages of a wallet pipeline because their required mathematical structures are mutually contradictory:

  • Public-Key Cryptography Demands Rich Group Structure: For digital signatures (ECDSA) and key pairs to function, points on secp256k1 must form an abelian group endowed with commutative point addition. The existence of an efficient group homomorphism (k → k · G) is the very foundation that allows public verification without exposing private scalars.
  • Hash Functions Must Annihilate Algebraic Structure: If a hash function preserved algebraic or linear relations (homomorphisms), attackers could construct algebraic shortcuts, length-extension attacks, or linear equation systems to forge preimages. Keccak-256 uses the sponge construction with 24 rounds of non-linear bitwise permutations (θ, ρ, π, χ, ι) specifically to maximize confusion and diffusion, obliterating all algebraic homomorphisms.
  • KDFs Must Impose Computational Inefficiency: Private keys must be fast to compute when signing, but master seed derivation (BIP-39) must deliberately be computationally expensive (via 2,048 PBKDF2 iterations) to defend human-chosen passphrases against high-speed GPU/ASIC dictionary attacks.
  • Checksums and Encodings Must Be Lightweight & Transparent: Checksums (EIP-55) prioritize backwards compatibility and human transcription safety without expanding data payload size (0 extra bytes) or requiring secret keys.

C. Chronological Evolution Timeline & Standards Divergence

1977
RSA Public-Key Cryptography: Rivest, Shamir, and Adleman establish asymmetric cryptography based on integer factorization hardness.
2001
SHA-2 Standard (FIPS 180-2): NIST publishes SHA-256 and SHA-512 based on the Merkle–Damgård construction.
2012
BIP-32 (Hierarchical Deterministic Wallets): Pieter Wuille formalizes deterministic derivation trees using HMAC-SHA512 with hardened/unhardened subkeys.
2013
BIP-39 (Mnemonic Code for Generating Deterministic Keys): Slush and Palatin standardize 12/24-word human-readable backups with PBKDF2 stretching.
2014
BIP-44 (Multi-Account Hierarchy for Deterministic Wallets): Standardizes the 5-tier path m/44'/coin'/account'/change/index.
2015 (Jul)
Ethereum Frontier Mainnet Launch: Ethereum adopts Guido Bertoni, Joan Daemen, Michaël Peeters, and Gilles Van Assche's original Keccak-256 sponge design for all hashing and address derivation.
2015 (Aug)
NIST Finalizes SHA-3 (FIPS 202): NIST standardizes Keccak but modifies the domain separation padding byte from 0x01 to 0x06. As a result, Ethereum Keccak-256 ≠ NIST SHA3-256.
2016
EIP-55 (Mixed-Case Checksum Address Encoding): Vitalik Buterin introduces backwards-compatible address checksums embedded into hexadecimal casing.
